# LLaDA 2.1：单块与双块 Q64

与 `hard` 共用完全相同的 30 个请求、种子、长度上限和质量判分。双块是新的前后块联合生成调度，不是原生采样路径；验证合同保证左块不能看右块、最后的 MASK 写入后仍须验证、提交时不能有 MASK。前缀变化时右块重新编码；初始化、校验、提交与重编码及投机算出的右块都计费，纯 prompt prefill 不算。

| 执行 | 质量 | 实测 TPF | token efficiency | 实际 Q/F | N | F | Q |
|---|---:|---:|---:|---:|---:|---:|---:|
| 单块 B32，名义 Q32 或 Q64 | 26/30 | 5.728 | 15.55% | 32.00 | 12,814 | 2,575 | 82,400 |
| 两个 B32，名义 Q64，无额外预留 | 24/30 | 5.609 | 9.17% | 50.13 | 13,161 | 2,863 | 143,513 |
| 两个 B32，名义 Q64，至多 8 个额外复查席位 | 24/30 | 5.609 | 9.17% | 50.13 | 13,161 | 2,863 | 143,513 |

两种双块策略使用相同调度。[逐请求](paired.csv)与[汇总](summary.csv)包含实际选位、总工作量和输出一致性：30/30 的输出、逐轮选位和阶段相同。在 1,773 个选位轮中，1,442 轮实算 64 行，331 轮可选行更少；所有轮都覆盖了当时所有可选行。“预留命中 445 次”只是把本来就被计算的行标注成预留，**没有增加一次独有命中**。这解释了两种预留策略的完全一致，不代表左块与右块的启动时机已经最优。没有可比的原始 IBS64/OBS64 LLaDA 基线。

复算指标：从 `paired.csv` 的 `noedit_N/F/Q` 或 `frontier_N/F/Q` 计算 `mean(N/F)`、`sum(N)/sum(Q)` 和 `sum(Q)/sum(F)`。运行入口 `python -m tools.run_dual_t2t --model llada21 --checkpoint MODEL --samples SAMPLES --reference NATIVE --output NEW_RUN`，默认同题顺序跑两种策略。两块绝对位置的 QKV hooks 和逐层 KV 行数在每个 forward 校验；未来若要在 Q64 内比较真正不同的选位，需要可选集合超过 64，而非把饱和运行当作排序消融。
