# 单请求跨块选 Q 与提前建 KV：终止复盘（2026-11-27）

**决定：终止这版 `00/10/11`，不补齐矩阵，不作为默认执行器。** 目标是任意给定的固定预算下，同时保持质量和 TPF，最好优于同预算 Optimus 或 FLowBlock。本轮在多个有直接对照的档位被超过；不否定真实稀疏 Q、块间因果掩码或尾部用余量处理后块本身。

- 输入与逐题轨迹留在 n164：`/data1/project_data/gx-erqw-20261123/runtime/t2t-native-1125/prefix90/` 下的 `block-ablation-{gemma,llada21}-v1`；未伪造 LLaDA 完成标志。两张卡归还 holder，此轮巡检取消。
- 质量是正确题数；TPF 是逐请求 `N/F` 的算术平均，token efficiency 是 `ΣN/ΣQ`。`N` 是最终解码 token 数，不把 T2T 当成又交付一个 token。用指标时看名义预算、每种 forward 的实际 Q 及模型的附加开销；Gemma 的跨方法总 Q 含 encoder 口径，不能直接用总 Q/F 判断是否突破 decoder 限额。[硬限额对照及成本字段](controls/fixed-family-references.csv)。

## 失败的机制与证据边界

1. **把“可以跨块”实现成了“两个块轮流拿名额”。** LLaDA Q16 的 `00→10` 是 42→22 题，TPF 只从 2.266 到 2.292。这个实现同时改变开块时机、两块的选位顺序和各自的推进速度，因此不能据此说跨块本身有害，更不能说因果掩码有害；掩码在这三组不是实验变量。
2. **`00` 不是原生解码器，两个模型在它身上丢的东西也不同。** LLaDA 新路径在块无 MASK、待刷新清空、该覆盖的行已覆盖时退休，没有旧版本的全块终检或独立 commit。因此最后一次写对 KV 不等于已解 token 不值得再看；但旧终检中发现 T2T 也不证明每个编辑都提升答案。Gemma 则相反：Q32 `00` 的 7,139 次 decoder forward 中，1,638 次只清待刷新位置、1,392 次终检，共 42.4%。这说明检查应从单块路径开始，不意味着这些轮次都能删。
3. **后块做过的计算不等于最终保留下的进展。** Gemma Q512 提前打开 117 个后块，34 个被丢弃，丢弃前已花 28,857 行；83 个晋升时因 encoder 上下文更新又刷新 21,248 行。前者是未保留计算，后者是上下文一致性成本，两者不能算成同一种浪费。只数「填满了多少 Q」会同时错过这两项。
4. **消融混入了预算和生命周期变化。** `10→11` 同时改变第一次可见的上下文、可采样的位置，并在 `q<B` 时给整建一轮超过档位的计算；`q=2B` 则三个开关组合退化到同一路径。能否用一定整建成本换回质量，和能否在给定硬预算获胜，是不同命题。尚无证据把失分单独归给前缀重算、T2T、尾部提前开块或采样时钟中的某一个。

## 建议下一步（未启动）

- 先用已有轨迹做逐题对照，而不是再开一张矩阵：LLaDA 优先看 Q8 的 14 道单向丢题以及 Q16 的救 3、丢 11；Gemma 区分只刷新、终检、尚可采样和后块作废的 forward。找到候选机制，不从已有输出倒推出“当时能看到”的 logits。
- 若另行启动下一轮，从**实际 Q 受限的单块 Optimus IBS 和各模型的原生采样方式**出发。统一的是预算约定、计费和待刷新记录，不强行统一两模型的块结束条件。每个档可直接起步；`q=B` 的原生行为是实现对照，不是强制任何请求从大预算启动。
- 每个模型只验证一个改动。LLaDA Q16：在块末给已解的块内位置一次**有上限的复核机会**，从当轮 Q 出，不漏掉新解码或 T2T 后必须刷新的行；分轮检查不声称等于原生全块终检。Gemma Q128：只在上下文版本有效且采样规则允许时，把同一 forward **已算出、可合法采样**的 logits 用于推进，保留确需的刷新与终检。两者都是可证伪假说，不是已有改进结果。
- 后块不是默认竞争者。以后要单验这点，应固定头块原有选位顺序，只在它确实没有可推进或值得复核的位置时才使用余量；提前解出的 token、被撤销或重算的 token、实际物理 Q 和额外 forward 分开记。`q=2B` 若按约定主动算两块，只和独立的双块基线对比，不解释为开关效应。
- 先冻结同一 30 题、同种子、同采样/结束语义、同硬上限，预先指定同档 IBS/OBS（整块再加 native/FLowBlock）。先看质量是否守住、TPF 是否守住以及至少一项是否提高，再看效率与分数据集的救/丢；硬上限和真实成本是前提。30 题只做淘汰，不宣告优胜。有信号才看另外 60 并同时报告完整 90、原 30 和配对不确定性。若只是以质量换 TPF，就报告取舍，不进入混合预算、Serving 编排或响应曲线阶段。
