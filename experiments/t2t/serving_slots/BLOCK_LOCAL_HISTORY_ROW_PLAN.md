# 当前块全算、按 Q 行重读历史：单请求验证方案

状态：方案与基线盘点；下表不含新方法成绩，不重启上一轮跨块消融。

## 每轮执行

1. 只打开一个物理块。令 `b` 是本块真实有效行数，`H` 是该层按模型原生 mask、位置与滑窗允许读取的 prompt 和已完成块的 KV。当前块中已解的连续前缀仍属于 `b`，不是 `H`。块内保留原生合法的双向边；不让未来块进入。
2. 外部给定固定档 `C`，不随样本或步数切换。重用原 [choose](../../../bdlm_serving/methods/t2t/budget_family.py) 的选行规则，行坐标都在当前块内；不做按列淘汰、不预测未来 logits。稀疏档有效名额 `min(C,b)`：先待重读的上次新解/编辑行，再未建立历史的行；常规轮在未解行和块内干净前缀间按原 `Law(1,8)` 分配，前缀有候选时才占位，保留可推进的未解位置。未消化的待重读记录不能丢；两种模型使用各自已有的未解/已编辑定义。`C>=b` 有能力整块读历史；定义为全读端点，不让启发式选位在该端点少选。对外分别报告这种端点和稀疏档，不能称全读端点是由 choose 自然选满。
3. 每层每个有效行都投影并计算块内注意力。只将选中行打包，与其完整合法历史计算 attention；保存每层、每头、每行的部分加权输出和对应的 log-sum-exp。未选中行复用上一步**上次实际重读**的历史输出与 LSE。用两侧 LSE 加权合并，不直接相加；然后所有有效行走原模型后续层。不通过全算历史后遮挡来模拟省算。
4. 有效历史从未建立的行，历史侧取空分区（LSE 为负无穷），可参与本地计算，但不允许凭空读缓存或先输出 token。在模型定义下本来就没有任何合法历史时，空分区本身是正确结果，不额外设采样障碍。不得免费用一次 `B×H` 起步。每个新块和 Gemma encoder 版本变更均按需失效。来自历史旧输出及 LSE 本来就是一种近似，不把它标成最新 KV。
5. 有有效历史、原生规则允许的行，可以采样及 T2T，包括本轮只更新了块内部分的行。不选历史 Q 不等于冻结本地 token。输入变化的行入待重读集合，实际重读成功后才消账（同轮再次编辑重新入账）；原选位器只负责分配历史名额，不直接接管原生采样时钟。若发生只还待刷新债务的轮次，也记 forward。保留各自原生采样、必要的收尾和缓存一致性检查；某项收尾若需全量读史须单列实际成本及超额，不得免费记为 `C`。
6. `C=2B` 作为计划槽位明列。本单块算法与 `C=B` 同为全读端点，验证逐轮轨迹等价，不开第二块也不伪造独立高档收益。对原版 IBS 也坚持原控制器与 IBS 边界，固定 chunk，关闭 hard cap；入口当前只白名单至 B。先验证上游对大 chunk 的实际语义：若仅等效饱和，明记端点引用；若不支持且不能等价证实，标 N/A，不以 OBS/双块代替，不冒充新增实测。

## 比较和验收

按同一 frozen90 输入、种子、输出上限与评分，拆出原30以及新增60。新策略中的模型原生采样不改。Gemma 仓库 IBS 是单调解码的 Optimus 适配，不含原生采样器的 T2T；它是用户要求的端到端基线，不是隔离某一个机制的对照。另留**同采样器的全读端点**作机制对照。原版 IBS 照常保留额外投影行。

1. 全读端点核对每层 attention、整模 logits、采样/编辑/结束轨迹；允许按实际 dtype 预先规定的数值容差，映射到答案和运行步数的分歧须说明。测试冷缓存、空历史、尾块、EOS 和 Gemma encoder 版本失效。
2. 实算形状与缓存审计：decoder Q 始终计所有投影行，历史 Q 只计实际与历史做注意力的行；记录合法注意力边数、初建/重读、过期复用、等待时长，区分只读本地的行贡献的解码和 T2T，检查 IBS 的实际 decoder Q 和超 nominal 次数。分开记 decoder/encoder、prompt prefill 与收尾，不重复计同一次 forward。
3. 各档报告正确题数、宏 `mean(N_i/F_i)`、总 token efficiency `ΣN/ΣQ_physical`；额外列每轮块内 Q、历史 Q P50/P95/max、Gemma encoder Q、同设备同 batch 的 ms/token 及前缀长度分层。输出 token 一次计数；T2T 不计新输出。注意力少算的边不是 token，不得加进 token efficiency 分子或换作分母。
4. 与原版 IBS 的判断为同名义槽位比较，不是同成本比较。逐题报告救/丢和配对区间。质量和 TPF 同时不降且至少一项提高才算该档达标；另独立判断时延及实际成本。全读等价、无偷算和不使用无效缓存是正式评测的前置条件。先 original30，再补冻结的其余60；不以30代报90。
