# 固定 Q：按连续前缀的进展决定是否刷新

这是 `fixed-q-prefix-and-tail-20261128` **之后**的独立试验，不修改该版本，也不采用等量分散选位。问题是：已经有进展的步可否少刷新前缀，把行留给 MASK 或直接不算，同时不牺牲整条请求的质量和 TPF？

**单一改动。** 普通采样计划开始时，从当前物理块首个生成位置起，数出连续的「已接受、已建立 KV、且不欠写回」位置数。若比同一块、同一缓存 epoch 上一次普通采样计划入口的长度严格增长，本次额外前缀配额置零；否则沿用父算法的右端配额。第一次没有历史，保留父配额。纯写回与终止验证不更新记忆，块或 epoch 变化清空记忆。Gemma 的冷启动采样也记录**计划前**的长度，但冷初始化选行不变。已写入/编辑的行仍必须支付；可替换的仅是已经付清的额外前缀。模型可有不同父配额。算法不读未投影行的 logits，也不使用本次采样结果。

## Gemma Live Q128：父算法 90 题同状态回放

父算法为 `dense_stop_joint_verified_eos`，可选份额 1/4，同卡 88/90、TPF 13.047、TE 11.97%。重建了 2,310 次 decoder 调用（253,634 Q），以及 74 次生成 encoder。1,567 次普通采样的实投行、采样行和原前缀行逐步一致。冷采样只记忆长度；初始 KV、欠写回和验证均不因本回放改变。计数只比较**原轨迹同一入口**的两个计划，各步不串成新轨迹。
