# 独立赛马提案：单请求固定预算下的块因果／尾部／前缀／切档

2026-11-28。独立提案，不代表既有结论，也不继承上一轮 `00/10/11` 的执行器。
只读 研究工作树 的文档与代码；未动集群、未动 Git。除本文件外无写入。

适用对象：LLaDA2.1（B=32）与 DiffusionGemma（B=256），单请求、batch=1、固定档 C。
评测口径：同题（frozen90，先过 frozen30 淘汰）、同种子、同输出上限 2048、同停止语义、同硬上限。

## 0. 一页结论

**首选（本提案的参赛马）**

> **P0 = 单前沿 · 块因果 · 债务优先 · 尾部只吃余量、且只读不采样。**
> LLaDA 用「整块全算 + 选行读历史」，档位 C16（硬预算 <B 时）或 C32（≥B 饱和端点）；
> Gemma 用「投影前选行」的稀疏 K0，档位 C128（膝点），质量优先走 C256 原生。

一句话：**块内全算与块因果不能省；债务闭合与真实计费不能省；跨块尾部、2B 并发、前缀重读、任意切档全都可以延期。**

三个判断，按可证伪程度排序：

1. **两模型的最优族不同，根因是 B。** LLaDA B=32 时整块全算很便宜，选行只该用在「读历史」上；Gemma B=256 时整块全算会把物理 Q 放大到 250 万级，选行必须前移到「投影」上。跨族照搬会在 Gemma 低档直接崩（C32：30/90、38 题截断、500 万级物理 Q）。
2. **"2B 类 FlowBlock 因果" 要拆成两件事。** 因果拓扑（块内双向、跨块只前→后）是**不变式**，实测更省 Q 且不掉质量（Q64：350,243→296,168 Q，72→73 题）。2B **并发预算档**是**被否决的预算模式**（LLaDA true64：69/90、多 51% Q；Gemma W2：742,912 Q 换 1.12 个活跃块）。把两者混为一谈，是上一轮最主要的语义混淆。
3. **任意档位切换在这两个执行器上还不是质量手段。** LLaDA 8↔16 两个相位都低于两个端点（相对 Q16 救2丢7 / 救3丢9）；Gemma 32↔64 质量在噪声内、总 Q 高于固定 64、非选位轮吃掉约 48% Q。默认静态档，切档只作负载杆，且必须另设计。

## 1. 口径（先钉死，否则赛马不可比）

| 符号 | 含义 |
|---|---|
| `B` | 物理块长：LLaDA 32，Gemma 256 |
| `C` | 每个**选位轮**的名义预算（不是每步，也不是总量）；外层固定，不随样本/步数改 |
| `q` | 单次物理前向实际投影的行数；硬上限要求 `q <= C`（LLaDA `q=2B` 是显式例外，见 I6） |
| `N` | 最终有效解码 token 数；T2T 改写不算新 token |
| `F` | 计费 forward 数（含 prefill 之外的 drain、verify、commit、re-encode、build） |
| TPF | 逐题 `N/F` 的算术平均 |
| 前缀效率 | `ΣN / ΣQ_prefixKV`（每轮每个选中读历史的位置计一行） |
| 物理效率 | `ΣN / ΣQ_physical`（所有真实投影行） |

三条硬规定：

1. **"固定预算" = 固定选位轮的 C。** 总 Q、总 F 是结果，不是约束。不许用 `C×F` 冒充实际工作。
2. **decoder / encoder / prefill 分开记**；Gemma encoder 重编码不占 decoder offer，但必须计费。
3. **失败与截断留分母**，不换题、不补测替换低分题。

参考实现位置：

- LLaDA 执行器 `bdlm_serving/methods/t2t/llada_budget_request.py`（`_inputs` / `_ablation_plan` / `_retire` / `_step`）
- 选位法 `bdlm_serving/methods/t2t/budget_family.py`（`choose`：dirty → cold → mask → prefix，prefix 上限 `min(room,b)*law.num//law.den`，并保留至少 1 个未解行）
- Gemma 双块 `experiments/t2t/serving_slots/gemma_fixed_dual.py`（`_dual_step`：`limit = min(fixed_q, B*len(states))`；`_spawn` 只在头块可采样且无 tail 时开尾）
- Gemma 稀疏 `bdlm_serving/methods/t2t/gemma_sparse.py`（投影前选行、`prefix_quota`、`_prefix_actions`）
- 上一轮三臂 `experiments/t2t/serving_slots/block_ablation.py` + `llada_fixed_family_eval.py` + `gemma_fixed_dual_eval.py`

## 2. 代码事实（本提案的地基，不是结论）

### 2.1 LLaDA（B=32）

- `_inputs(q)` 只看 `head` 起 `ceil(q/B)` 个块；**每块必须内有 MASK 才成为候选**；`prefix` 只取「最低 MASK 之下、已初始化、非 dirty」的连续行。
- `choose` 顺序固定：**dirty 必选** → cold（从未建 KV 的 MASK）→ 未解 MASK → 前缀（上限 1/8 且至少留 1 个未解）。
- `_ablation_plan`：`q==2B` **无视档位一律 dense_joint**（两块全行），所以 `00/10/11` 在 Q64 退化成同一条路径——这解释了三组 Q64 数字相同。
- `q<2B` 时开尾门的条件是 `last_end >= head+B` 且 `4*头块MASK <= 32`（即头块剩余 MASK <= 25%）。`11` 额外允许 `build_sample`：一次**超出 offer** 的整块前向（`cap=len(rows)`）。这是预算违规的来源。
- `_retire` 要三件事同时成立：整块已完全驻留（`end <= bank.last_end`）、块内无 dirty、块内无 MASK。
- `_step`：unresolved 且 `conf>0.9` 接受；非 MASK 且 `conf>0.5` 且新值≠旧值可编辑；编辑回 MASK 记为 revoked 并进入 dirty。**写过的行必须重读**（`written` 并入 `self.dirty`）。
- `_Bank.begin` 拒绝 KV 空洞；`visible_end` 是可见高水位。**没有"预测一个未来 KV"的口子**。

### 2.2 Gemma（B=256）

- `gemma_fixed_dual`：`_spawn` 只在「头块可采样、非 rebuild、无 tail」时开尾；`limit=min(fixed_q, B*len(states))`；`choose` 的 cold 是整块 256 行——所以真正开双块时，尾部是一整块 cold，会被一次性采样。
- 因此 `Q512` 在已评分矩阵里**不是双物理块**：它走 `dispatch-v1` 回原生 SDPA，与 C256、原生逐题同 ID/F/Q（N=31,352，F=1,397，Q=357,632）。**Gemma 没有经过验证的 2B 稀疏档**；W2 是另一个执行器（FlowBlock），不能当同档位。
- 稀疏族（K0）在投影前选行，`prefix_quota` 决定前缀；前缀动作有 lock，`_prefix_actions` 会回滚与 accepted 不一致的写入。**前缀不是免费读，是可撤销的写**。

### 2.3 一个被忽略的硬约束

LLaDA C8/C16 的「整块全算」每轮投影 32 行，物理效率（8.68%/12.01%）**低于** IBS（28.22%/20.51%）。
Gemma C32/C64/C128 的「整块全算」物理效率只有 1.93%/1.99%/3.10%，而稀疏 K0 是 13.73%/12.71%/11.18%。
**"选行读历史"这个机制在小 B 上划算，在大 B 上不划算。** 这是本提案与上一轮最重要的分岔。

## 3. 只读证据摘要（判"不能省/可延期"的依据）

### 3.1 LLaDA `00/10/11`（同 66 题，硬限额对照为 OBS）

| 名义 Q | 00 | 10 | 11 | OBS |
|---:|---|---|---|---|
| 4 | 13 / 1.095 | 12 / 1.379 | 30 / 1.495 | 51 / 1.433 |
| 8 | 21 / 1.411 | 15 / 1.640 | 39 / 2.179 | 53 / 2.323 |
| 16 | 42 / 2.266 | 22 / 2.292 | 46 / 3.107 | 54 / 3.384 |
| 32 | 55 / 3.856 | 44 / 4.316 | 49 / 3.804 | 原生 56 / 5.248；W1 55 / 6.438 |

读数：

- **交错双块（10）是三种里最差的**（Q16：42→22）。"可以跨块"被实现成"两块轮流拿名额"，同时改了开块时机、选位顺序、推进速度。**不能据此说跨块本身有害，但足以说这个实现不能当默认。**
- **`11` 的整块 build 是超预算换质量**：Q16 有 1,071 次 decoder forward 高于 16、峰值 32；对 OBS 救 3 丢 11。硬上限下不可用。
- **`00` 不是原生**：块无 MASK + 待刷新清空 + 已覆盖就退休，没有全块终检。它的 Q16=42 是"省掉检查"的代价，不是"跨块无效"的证据。

### 3.2 块因果掩码（LLaDA Q64=2B，同执行器，90 题全触发）

| 臂 | 正确/90 | 宏 TPF | 效率 | 计费 F | 实算 Q |
|---|---:|---:|---:|---:|---:|
| 关掩码 | 72 | 5.932 | 11.76% | 8,832 | 350,243 |
| 开掩码 | 73 | 6.561 | 13.79% | 7,178 | 296,168 |
| 原始 FlowBlock W2 | 74 | 10.006 | 11.61% | 5,594 | 358,016 |

TPF 差 +0.629，配对 95% 区间 [+0.322, +0.935]；Q 少 54,075；质量 +1.11pp（区间跨零）。
**结论只能写到：开掩码更省且不更差，不能写成"提质"。** 但足以把"块因果"放进不变式。

### 3.3 合并提交不是无损（LLaDA，6 个真实转移）

| 后端 | 头 KV 不逐位同 | 尾 KV 不逐位同 | 后块 logits 最大差 | 当轮 token 不同 |
|---|---:|---:|---:|---:|
| CPU BF16 | 5/6 | 6/6 | 2.250 | 1/6 |
| GPU BF16 | 4/6 | 6/6 | 3.250 | 0/6 |

**"头提交 + 尾刷新合成一次 64 行前向"不能假设等价。** 尾部晋升必须重建/复核，不能靠"KV 应该一样"。

### 3.4 LLaDA 真双块 Q64 与原生 B32

| 真双块 Q64 | 69 | 5.831 | 9.86% | 7,960 | 395,363 |
| 原生 B32 | 75 | 5.677 | 15.56% | 8,182 | 261,824 |

真双块救 5 丢 11，TPF 区间 [−0.108, +0.415]，**多用 51% Q**。2B 并发不能当默认高档。

### 3.6 Gemma 两族固定档（90 题）

| 档 | 整块全算+选行读历史（TPF/物理效率/截断） | 稀疏 K0（TPF/效率/Q） |
|---:|---|---|

**Gemma 的"整块全算"族在 C<B 时已经出局**；它的 256 档其实就是原生。稀疏 K0 才是 C<B 的前沿。

### 3.7 切档与驻留（Gemma）

| 供档 | 全90 | TPF | 效率 | F | 物理 Q |
|---|---:|---:|---:|---:|---:|
| 固定 32 | 83 | 8.463 | 13.73% | 4,023 | 240,190 |
| AABB（32,32,64,64） | 82 | 10.472 | 12.84% | 3,265 | 254,468 |
| BBAA（64,64,32,32） | 83 | 10.559 | 12.83% | 3,362 | 260,838 |
| 固定 64 | 83 | 12.897 | 12.71% | 2,562 | 250,795 |

- 两种混合的 TPF 在端点之间，但**总 Q 都高于固定 64**；非选位环节占 47%–48% Q。
- 驻留 8 轮 vs 2 轮：先 32 是 79 vs 82（变差）；先 64 是 84 vs 83（TPF 区间 [+0.053, +0.826] 但新 60 少 1 题）。**不构成"少切更好"的统一规则。**
- 切档时右端 K8 补空位：两个相位都是救 0 丢 0，累计补 577/643 行、约 12 万 Q，TPF 方向不一致。**前缀补位不是切档的解药。**

### 3.8 Gemma 128↔原生256 与 tail 门控

- `128→256` 循环 86/90（最好），但 TPF 22.357 < 25.510，Q 346,119 vs 357,632，F 多 288；`256→128` 84/90。**净差 1 题，不能当稳定收益。**
- 只在 `MASK<=64` 使用高档：84/90、19.574、11.19%、286,607 Q；全接收 86/90、22.357、9.49%、346,119 Q；同相位 IBS 80/90、18.898、11.01%、289,152 Q。**tail 门控省 17% Q、掉 2 题，质量/TPF 的配对区间跨零。** 这是唯一有正面信号的"尾部"实验，但还不够格当默认。

### 3.9 上一轮复盘的失败归因（原文要点）

- `00→10` 实现成"两块轮流拿名额"，不能归因到跨块或掩码。
- `00` 不是原生，两模型丢的东西不同（LLaDA 无全块终检；Gemma Q32 `00` 有 42.4% 的 forward 只清待刷新/终检）。
- 后块计算 ≠ 保留进展：Gemma Q512 提前开 117 个后块，34 个被丢弃（丢弃前 28,857 行），83 个晋升时又刷新 21,248 行。
- `10→11` 同时改了上下文、可采样位置、预算；`q=2B` 三开关退化。**没有任何单因素归因成立。**

## 4. 不能省（不变式；违反就不是同一个模型/同一笔账）

| # | 不变式 | 违反会长什么样 | 依据 |
|---|---|---|---|
| **I1** | **活块全投影**：当前块每个有效行都要投影 QKV 并算块内注意力；能省的只有"读历史" | 少投影行 ⇒ 少了 KV 写入 ⇒ 下游可见性断裂；或偷偷用旧输出 | C8 每轮仍投影 32 行；"少读历史的工作量是真实减少的，但每一步仍投影整个当前块" |
| **I2** | **债务闭合**：写/编辑/revoke 的行在下一次被当历史用之前必须重读；降档不得丢未刷的尾块写入 | 未刷行被当历史 ⇒ 近似缓存冒充最新 KV；降档丢写 ⇒ 静默改答案 | `self.dirty=(before-rows)∪written`；`_retire` 要求块内无 dirty；`choose` dirty 必选且允许降档溢出 |
| **I3** | **块因果**：块内双向；跨块只前→后；不读未驻留/过版本 KV | 头块读后块未定稿 KV ⇒ 上下文泄漏；KV 空洞 | 掩码开关：Q −54,075、TPF +0.629 [0.322,0.935]、质量 +1pp；`_Bank.begin` 拒绝空洞 |
| **I4** | **可见性资格**：只有已初始化且版本一致的行可读；Gemma encoder 边界必须精确 | `Wrong encoder boundary` / 读旧 encoder 上下文 | `gemma_fixed_dual._project` 的边界断言 |
| **I5** | **真实计费**：prefill 之外所有前向都计 F；drain/verify/commit/re-encode/build 全算；encoder 与 decoder 分列 | "名义 Q×F" 当工作量；把终检当免费 | Gemma 切档非选位轮占 47–48% Q；`11` 的 1,071 次超档 forward |
| **I6** | **硬上限**：单次实际 decoder Q <= C（LLaDA `q=2B` 是显式登记的例外，必须单列） | 用峰 32 的 forward 去比 16 档 | Q16 `11` 峰值 32 vs OBS 不超 16 |
| **I7** | **端点复现**：关掉新机制必须逐题复现同档旧执行器（输出 ID、F/Q、事件、停止） | 新机制把旧路径改坏了还不自知 | 切档实验的前置资格；`--slot-control` |
| **I8** | **同题同种子同上限同停止语义 + 失败留分母** | 换题、补测、挑相位 | frozen90 / original30 的既有约定 |

**注意 I1 与族选择的关系：** I1 说的是"活块投影不能省"，不是"投影必须包含全部 B 行"。Gemma 的稀疏 K0 在**投影前**选行，是合法的另一种"活块定义"；但一旦选定，被选行必须全投影、全写 KV。这是两族都守 I1 的方式。

## 5. 可延期（每一项都有复活条件）

| # | 可延期项 | 现在怎么做 | 复活条件 |
|---|---|---|---|
| **D1** | 跨块尾部（提前建/提前采样） | 默认关；只在头块**零可推进**且有余量时，只读建 KV，不采样 | P0 在同题 30 题上质量不降、且尾部使下一块启动提前 >=1 轮，Q 增幅 <=5% |

| **D8** | 调度器、混批、跨请求编排、响应曲线 | 不做 | 单请求三指标已稳定，且 D5 有正结果 |

## 6. 首选 P0（完整规格）

### 6.1 执行规则（两族共用骨架）

1. **一个前沿。** 只有 `head` 块的行可以采样/编辑/revoke。`tail` 永不与 `head` 同轮采样。
2. **块因果。** 块内双向；跨块只允许前→后；不读未驻留/过版本 KV。
3. **每轮全投影。** 被选中的活行全投影、全写 KV；块内注意力全算。
4. **名额分配。** `dirty` 必选（可溢出）→ cold MASK 必采样 → 未解 MASK → 前缀（默认 0）。
5. **尾部只吃余量。** 仅当 `dirty=∅`、头块无未解 MASK、无可用前缀、且头块已完全驻留时，才用剩余名额对 `tail` 做**只读**建 KV；`tail` 不采样、不入 `tokens`，下一轮若头块有活可做则丢弃尾部进展（计费照付）。
6. **退休条件不变。** 整块驻留 + 无 MASK + 无 dirty；EOS 截断 + `invalidate_from`。
7. **切档只是改 C。** 不改 RNG、不清缓存、不改块边界、不重置 `sample_clock`；downshift 先还债。

### 6.2 两族的差别（这是本提案的核心）

| | LLaDA（B=32） | Gemma（B=256） |
|---|---|---|
| 族 | 整块全算 + 选行读历史 | 投影前选行（K0 稀疏） |
| 为什么 | 32 行全投影便宜；裁到 4 行会让 C4/C16 的读数失去意义 | 256 行全投影 = 250 万级物理 Q、TPF 腰斩、低档大量截断 |
| 档位 | C16（预算 <B）；C32（>=B 饱和） | C128（膝点）；质量优先 C256 原生 |
| 对照端点 | 原生 B32、OBS 同档 | 原生 256（= FlowBlock W1）、IBS 同档 |
| 预期 | 质量 74–76/90，TPF 4.2–5.6，物理效率 12–15% | 质量 84–85/90，TPF 17–25，效率 9–11% |

### 6.3 为什么不是别的

| 备选 | 为什么不选 |
|---|---|
| `11`（build_sample） | 违反 I6；Q16 峰值 32、1,071 次超档、对 OBS 丢 11 |
| `10`（交错双块） | Q16 42→22；实现同时改了三件事，不能当机制对照 |
| 真双块 Q64 | 69/90、+51% Q；比原生少 6 题 |
| Gemma W2（FlowBlock 双块） | 742,912 Q 换 1.116 个活跃块；84/90 |
| Gemma C512 | 名义档，实际走原生 256；不是 2B |
| IBS 作为 LLaDA 默认 | 质量 71–73，低于整块全算族的 74–76；省的是物理 Q，不是质量 |
| 整块全算作为 Gemma C<256 默认 | 30/74/83 题、TPF 4.4/4.9/8.2、物理效率 2–3% |
| 任意切档 | LLaDA 两相位都低于两端点；Gemma 净差 1 题、总 Q 更高 |

## 7. 赛马（分轮淘汰，不铺全矩阵）

### 第 0 轮：资格（不计分）

每个参赛马在**关掉新机制**时必须逐题复现其母执行器同档旧记录（输出 ID、F、Q、每轮位置、停止事件）。否则出局，不进入评分。

### 第 1 轮：30 题淘汰（每模型 2 档）

| 马 | 机制 | LLaDA C16 / C32 | Gemma C64 / C128 |
|---|---|---|---|
| **A0** | 母执行器（H0） | ✓ | ✓ |
| **A1** | A0 + 尾部余量只读 | ✓ | ✓ |
| **A2** | A0 + 前缀 0:1（去掉 Law 1/8） | ✓ | ✓ |
| **A3** | A1 + A2（= P0） | ✓ | ✓ |
| **A4** | A0 + 尾部余量**可采样** | ✓ | ✓ |
| **A5** | A0 + 掩码关（诊断，不计入冠军） | ✓ | N/A（无受控实现） |

规则：任一行 30 题净负 >=2 且无 TPF 收益即淘汰；A5 只用于检验 I3，不与冠军争。

### 第 2 轮：90 题确认（每模型 <=2 马）

幸存者 + A0 + 外部参照（LLaDA：原生 B32 / OBS 同档；Gemma：原生 256 / IBS 同档）。报三组（原30/新60/全90）+ 配对区间。

### 第 3 轮（条件启动）：切档子赛马

只有当某个静态档已确认（第 2 轮冠军）才启动。外部供档序列固定多重集：

- `AABB`、`BBAA`、`R`（同多重集随机序，种子固定）、`dwell4`（每档连续 4 个选位轮）。
- 对照：固定 A、固定 B、同多重集匹配。
- 每个选位轮消耗一个元素；非选位轮不消耗但计费。
- 不许进 2B；不许换题；短请求保留。

## 8. 反证清单（预注册的 kill criteria）

每条都要能"被自己的数据杀死"。阈值先写死，跑完不改。

| # | 假设 | 反证（出现即改结论） |
|---|---|---|
| **F1** | 尾部余量只读能省 idle 轮 | 30 题相对 A0 净负 >=2，或 Q 增幅 >10% 而 F 不降 ⇒ 删 D1 |
| **F2** | 尾部余量从不触发（无机会） | 触发率 <5% 题 ⇒ 机制无意义，报告 null，不写"有效" |
| **F3** | 块因果是净收益 | 掩码关在配对中质量 >= 开 +2 题且 Q 不更差 ⇒ 重开 I3 |
| **F4** | 2B 并发是劣档 | 受控双块在硬上限下质量 >= 单块 +2 且 Q 增幅 <=2% ⇒ 2B 转正 |
| **F5** | 前缀 0:1 更省 | 前缀 1:8 救 >=2 题且 Q 增幅 <=2% ⇒ 保留前缀 |
| **F6** | 切档不是质量手段 | 任一混合臂打败两个静态端点之一且另一端点非劣（p<0.05 / Q CI 排除 0）⇒ 重开 D5 |
| **F7** | 驻留/探索无稳定收益 | dwell4 相对 dwell2 配对 CI 排除 0 且方向可复现 ⇒ 重开 D6 |
| **F8** | 30 题信号可外推 | 冠军的新 60 净收益 <=0 或方向反转 ⇒ 只报"30 题现象"，不许进 90 结论 |
| **F9** | C4=78 不是噪声 | 配对复测 C4 相对 C16 净胜 >=2 且 CI 排除 0 ⇒ 预算单调性假设作废，重排档位 |
| **F10** | 真双块/合并提交无损 | 复测出现 >2/6 转移的 token 分叉 ⇒ 永久禁止"KV 等价"假设 |

## 9. 配对实验协议

### 9.1 统计

- 质量：逐题配对 **McNemar 精确检验**；报"救回/丢失"两个数，不只报净值。
- TPF：逐题 `Δ(N/F)`，按数据集分层 bootstrap 10,000 次，报 95% 区间。
- 效率：先按同组求和再相除（`ΣN/ΣQ`），不平均逐题百分比；同时报物理口径。
- 多重比较：第 1 轮每个模型只有 5 个非诊断臂，不做跨臂择优；第 2 轮只比预注册的 1–2 个。

### 9.2 必报字段（每请求）

`index, dataset, task_id, seed, C, cap, output_ids, N, F, correct, truncated,`
`decoder_F, decoder_Q, history_Q, local_Q, prefix_Q, verify_Q, commit_Q, build_Q,`
`encoder_F, encoder_Q, prefill_Q, overflow_Q,`
`per_round: offer, q, phase(sample/drain/build/verify), rows, sampled, dirty_before/after, retired_blocks, tail_opened, tail_kept`

### 9.3 分阶段成本表（必须单列）

| 阶段 | 计入 | 不计入 |
|---|---|---|
| prompt prefill | 是 | — |
| 采样轮 local | 是 | — |
| 采样轮 history | 是（按选中行） | — |
| drain / verify / commit | 是 | — |
| build_sample / 整块超档 | 是，且单列超额 | — |
| Gemma encoder 重编码 | 是（decoder 之外） | — |
| 未保留的尾部进展 | 是 | — |

**"未保留的尾部进展"和"晋升后的一致性刷新"必须分开记**，这是上一轮 Gemma Q512 的教训（28,857 行丢弃 vs 21,248 行刷新）。

### 9.4 报告结构

1. 资格复现表（逐题 ID/F/Q/事件的 diff 数）。
2. 三组指标表（原30 / 新60 / 全90）× 冠军与对照。
3. 救/丢逐题清单（带 index，便于复核）。
4. 分数据集（GSM8K / MATH500 / HumanEval）拆分。
5. 失败/证据边界：哪些是跨机、哪些是单次、哪些是"只改一项"的。

## 12. 本提案的自我反证（如果只能记住一句）

**如果 P0 在 30 题上与 A0 完全同分同 Q（尾部从不触发或触发后无收益），那 P0 就是 A0，尾部机制应删除而不是保留为"可选优化"。**
这条比任何"预计提升"都重要：上一轮的问题不是缺机制，是把没有证据的机制留在了默认路径上。
