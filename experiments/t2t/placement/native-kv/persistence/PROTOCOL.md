# Gemma: can yesterday's observed per-row KV change predict today's?

Frozen after inspecting censored-label coverage, **before exact recapture**. Original 30 requests, native B256, L15, same sampler seeds. Not a new quality or TPF experiment.

1. For each request and native canvas, project the existing zero-reserve selector at each of Q16, 32, 64, 128, 256 on identical native prestates. First step is full bootstrap; later layouts preserve all preceding fresh and the usual MASK-first filling, including any mandatory overflow. Reset history between canvases. Do not use hypothetical replacements to rewrite the projected history. No serving-time pretense: the hidden states and writes remain those of the native run.
2. Only consider replacing the last ordinary **old backfill**. Every other seat stays put; no MASK or mandatory refresh can be displaced. Candidate set = that donor plus currently unselected nonfresh resolved rows, then intersect both `Q[t-2]` and `Q[t-1]`. If fewer than two options survive, or no outside row exists, keep base. The original donor need not have a measurable lag to serve as the no-change control.
3. Rank by the largest **prior** `max(relative_rms(dK),relative_rms(dV))` between the two preceding rounds at the same local row, ties to the smaller row. Score against **current** native old-pool high drift (the pre-existing joint top-10% definition, tie/floor convention preserved). No logits, current labels, threshold learned from this run, or comparisons of the K/V of unexecuted rows enter the predictor. Eligible options formerly MASK/fresh get the same measurement as prior old rows. This matters: the old archive did not retain such rows' lag magnitudes.
4. First bracket possible hit counts using censored historical data. Then recover the exact lag choices by observing the original native run, with no extra model forwards or RNG use. Keep only scalar relative changes, not K/V tensors. Require identity, output, work and trace parity with the previous native run; exact selection must fit the censored bounds. Report every Q, the number of contests, hits on the last seat, total baseline vs selected hits, gains/losses, neutral-row changes and within-option uniform expectations. No contest is not a miss. Q256 must remain identical.
5. A screen to justify a *subsequent* actual sparse rollout: require strictly more hits than both the measured baseline and the within-option random expectation in at least two of Q32/Q64/Q128, with no loss to either on the remaining one. Q16 is descriptive because the existing projected history has only four contests. Passing would justify testing, not establish that more drift-refresh hits improve quality, TPF or wall time. Failure does not establish that sparse resident-drift history in general is useless.
