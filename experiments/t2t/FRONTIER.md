# 不读 logits 的三部分 Q 预算

**要检验的假设。** 当一处 token 在邻居上次参与 Q 以后才被写入，邻居保存的表示可能已经过时。只用位置和写入时间对已解码的旧位置排序，不观察 logits、概率、注意力分数或未选行的 KV；这是对可能需要复查的位置的预测，不是对 KV 变化幅度的实测。

1. 硬选上一轮新接受或发生严格 T2T 的位置，以写入后的 ID 刷新其缓存。真正的 T2T 是已接受的非 MASK token 在下一步仍被接受、但 ID 改变。Gemma 撤销接受不是 T2T。
2. 剩余空间有 MASK 时至少给一个 MASK；在保留这个名额后从非 fresh 已解码位置选额外复查席位。其余给 MASK，不足再用相同规则回填。`hard_noedit` 将额外预留归还 MASK；`hard_random` 与 `hard_frontier` 只改变额外席位排序。`fresh=0` 在这三种配置名称里表示**没有固定 fresh 配额**，不是不刷新。
3. 每个请求以实际 Q 行运行，未选行不重新算模型。预填不计入生成；bootstrap、完整验证、提交或块间重编码全部收费。必刷行比名义预算还多时显式报告溢出，不能把名义 Q 当作每轮严格上限。禁止用补充审计的额外计算换取没有记账的 TPF。

**第一组实验。** 固定 30 题及种子，LLaDA Q=4/8/16/32/64；Gemma Q=16/32/64/128/256。单个 B32 块最多 32 个不同位置，Q64 的单块运行属于饱和对照，不是同时计算两个块；B256 的 Q256 同理。不同预算首先比较同预算的无额外席位、均匀随机和邻近写入三种配置。完整块只跑一组并逐题核对原生输出和实际计算。质量分为答对数/30；TPF 为逐请求 N/F 再取均值；token efficiency 为 ΣN/ΣQ。质量和 TPF 都是端到端实测量，不能从轨迹命中率推算。

**同状态覆盖诊断。** `python -m tools.frontier_replay --raw VERIFIED_RAW_ROOT --out OUTPUT.csv` 在两个模型的原生轨迹上，先用已发生的写入和模拟 Q 时间选位，再打开当轮标签。输出 hard fresh 本身覆盖的正例、旧位置的正例、预留席位的实际命中、同池同席位的均匀期望、相同席位下知道答案的覆盖上界，以及回填后的覆盖。固定原生写入路径（包括原生轨迹中写在模拟 Q 外的位置）是有意的离线条件；不得把这些已知位置照搬到已分叉的线上轨迹，或把覆盖上界称为质量/TPF上界。holdout 是每个数据集按冻结清单最后三题，题目此前已有研究使用。

[完整覆盖表，含 21/9 分组](frontier-native-coverage.csv)。LLaDA 原生共有 754 次严格 T2T：443 次位于 mandatory fresh，311 次在其外。Q16/E2 的 2,430 个预留席位命中 65 次（精度 2.67%；覆盖 65/311），均匀期望 29.41，同席位透视上界 242。包含其他回填计算后，整套位置集合覆盖 536/754；零独立 edit 的 Q16 为 481/754。Q16/E4 为 109 个预留命中，对照 58.61、上界 291。Gemma 全部 10 次严格 T2T 都在 mandatory fresh 中，额外候选池的分母是 0，不能报告额外召回率。这些值均非在线答案质量。

**可复现的在线调用。** 原生张量资格校验、冻结题单与原有 T2T 共用入口。用 `python -m tools.run_t2t --model llada21 --checkpoint MODEL --samples SAMPLES --reference NATIVE --output NEW_RUN --arm 16:0:16:hard_noedit --arm 16:0:14:hard_random --arm 16:0:14:hard_frontier` 比较 Q16/E2；Gemma 同理。随机排序种子随请求和步号决定，未预留的多余席位使用相同的中性回填。完整运行再用 `python -m tools.t2t_results --samples SAMPLES --run NEW_RUN --out NEW_SUMMARY_DIR` 判分汇总。

### 稀疏轮真正能选回哪些编辑？

上面的原生回放在每个非首轮上都模拟选位，包含其实会全算的验证轮。按在线 LLaDA 的阶段分开，754 次严格 T2T 中有 224 次在全算的验证轮（含 120 次旧位置），530 次在仍有 MASK 的去噪轮（339 fresh，191 非 fresh）；bootstrap 没有严格 T2T。**额外选位可挽回的原生目标是这 191 次**，不是 754 或 311。Gemma 的原生旧位置严格 T2T 分母仍是零；这不排除稀疏轨迹另外出现编辑，也不代表 KV 没有变化。

增加一个纯位置的逻辑回归预测器 `hazard`：输入包括距 MASK、上轮写入和上轮严格编辑的距离，最近写入的年龄，邻近写入在左/右哪一侧等；没有 token ID、题型、概率、logits 或注意力分数。按整题分成 5 折，每折留出各数据集 2 题，系数只拟合其余 24 题。测试样本曾用于本项目模型设计，不能视作外部盲测；这是原生条件下的交叉验证，不是使用额外模型推理得到的线上质量分。

### 在线预算变化与透视实验

- `hard_slack`：硬刷新及现有 MASK 全部容纳之后，再从多余席位中按预测排序复查旧位置。与零预留对照在**同一个前置状态**上分给 MASK 的行数相同，但之后轨迹可以分叉。
- `hard_trigger`：在上述规则之外，若没有多余位置，且上轮出现严格 T2T，才允许临近该编辑的旧行挤占最多一个 MASK 席位。首个 MASK 仍受保护。只使用历史已执行写入，不使用 logits。
- `hard_oracle1`（LLaDA 诊断专用）：从在线当前状态的零预留选择出发，在不改变必刷行、至少保留一个可选 MASK 的条件下，尝试一次换位。先在只读 KV 上用“原选择 ∪ 未入选旧行”筛候选，再从相同前置 KV 按实际部署宽度验证一个换位；只有确实会严格 T2T 才换入。真实推理重新执行所选行并断言结果；探针不更新真实 KV、RNG 或 token。联合筛选可能漏掉仅在某个单独换位下才会编辑的位置，故**不是穷举最优 oracle**。`oracle_union`、`oracle_trial` 的每一行和每次 forward 都计入物理 ΣQ、F、TPF、效率；无探针耗费的理想化估算只能另行标记，不能当作实测性能。

这些实验的分母、在线阶段和物理预算各不相同。[首轮在线结果及原始 IBS/OBS 对照](hard/README.md)。
