# Does the *write* on a predicted old row explain the Q4 gain?

## Frozen contrast

Use LLaDA 2.1 B32 on n164, same 30 benchmark identities, seeds, cap, fees, checkpoints and stopping rules as the published `hard_exchange_edit4` run. Run Q4/E1 and Q8/E1; Q4 is the earlier positive and Q8 the earlier negative. These are selected retrospective budgets, not a new held-out validation set. No subsampling or skipping requests that never edit. Run original full-width qualification independently before each arm.

The instrumented alternative uses the exact original fourfold rate table, fresh-first policy including overflow, MASK protections and candidate comparison. Every selected row really runs; attention/KV refresh, sampling and conditional model computation are unchanged **on identical input**. If and only if the selected *additional entrant that the same-state zero-reserve layout would not compute* would undergo a strict resolved non-MASK A to distinct non-MASK B write, veto that write. MASK admissions, revocations to MASK, edits on fresh/ordinary old rows, and unreserved bootstrap/verify/commit are unchanged. Subsequent fresh marks, applied edit counts, stopping, selections and charges use actual results, never the rejected proposal. The mode does not request any extra forward or previous unselected logits.

The primary mechanistic endpoint is the paired difference (write enabled minus veto) on correct count and macro TPF in all 30 requests at each budget. Report wins/losses against noedit too, and whether the Q4 uniquely recovered answer remains correct when entrant writes are forbidden. If it remains correct, direct entrant writes are not necessary for that particular rescue. A difference in either direction on a triggered request is an effect of permitting writes *and all subsequent consequences*, not proof that a specific first edit is good/bad in isolation. On a request with no blocked write, outputs, Q/F and original event fields must agree exactly. If the two arms do not match before the first blocked write, do not publish a causal interpretation.

Secondary: physical Q on each layer; per-request first blocked clock, total attempted vs applied edits, physical fresh/MASK/old-neutral/additional seats, whole-path N/F/Q including all initialization/verification/commit. Report actual correct/30, mean per-request N/F, pooled N/physical Q, and stratified paired bootstrap intervals. Historical Optimus IBS/OBS only contextualize nominal budget. Report same-input contrasts and aggregate results separately. The noedit reference differs in placement and does not isolate the write. A veto is a diagnostic, not a proposed default; do not silently include it in a winner search. Separately examine the history of the write-enabled arm before the veto results: grouping by whether a request has a direct entrant edit is descriptive, not randomized.
