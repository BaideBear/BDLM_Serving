# 研究备忘录：把部分已解码前缀放回计算窗口

2026-11-26，按研究者澄清更新。核心问题是：**哪些原本被跳过的已解码前缀位置，值得在固定 Q 预算内重新计算？** 预测下一步严格 T2T 或 KV 变化只是选位手段；不要求选中的位置一定改写 token，最终看同题质量、TPF 和物理成本。

## 研究范围与判据

本轮只研究带 T2T 的 **LLaDA 2.1-mini** 和 **DiffusionGemma 26B** 的单请求推理。两者分别报告，不跨模型汇总成败。LLaDA 2.0 和 SDAR 只留在历史实验档案，不作为本轮结论的依据。

- LLaDA 2.1：原生块宽 32，名义 Q 为 4、8、16、32、64。区分当前块内的稀疏去噪、整块验证以及跨块提交。Q64 若仍只在一个 B32 内运行，必须标为饱和对照。
- DiffusionGemma：原生 canvas 宽 256，名义 Q 为 16、32、64、128、256。用是否已接受而不是 token ID 是否为 MASK 确定旧位。接受、撤销接受、已接受 token 改写分开记账，只把第三种记作严格 T2T。
- 成功标准是各模型在相同 30 题、同名义预算下，相对零加回有更高的答对数且 TPF 不降，并报告实际 Q 和 token efficiency。信号是否有选位价值，还要对比同席位随机。旧位 T2T 命中、KV 漂移都只解释机制，不能代替质量分。

## 已确认的事实

原 [FlowBlock PrefixCache 实验](../flowblock-prefix/README.md) 保留活动块内已编码、未再修改的连续生成前缀的 KV，后续位置仍可注意它；省掉这些前缀行本轮的 forward，而不是从注意力中删除它们。块间掩码和窗口推进不变。[缓存实现](../../bdlm_serving/methods/flowblock/prefix_cache.py)。

同模型、同 W、相同 30 题，表内是原版 → 跳过前缀重算的正确题数：

|模型|W2|W3|W4|
|---|---:|---:|---:|
|LLaDA 2.1-mini|27 → 23|23 → 21|25 → 22|
|DiffusionGemma 26B|未测|未测|未测|

在固定 30 题上，LLaDA 2.1 三个 W 各少答对 4、2、3 题，不证明每个样本或其他模型都会退化，也不能区分陈旧 KV 和禁止该行继续改写 token 各自的影响。Gemma 没有这组质量对照；[原生轨迹](FRONTIER.md)的 10 次严格 T2T 都在上一步刚写过的必刷位，因此不能用额外旧位的 T2T 召回来判断它是否需要刷新前缀 KV。已有的“在所有非 fresh 旧位置中选位”结果不能改称“只从退休前缀加回”的验证；用已提交 token 的历史做特征，也不等于把这些历史 token 放回 Q。

## 接下来的直接对照

1. 逐步明确候选集合：每个活动块内，原前缀规则本步确实会跳过的连续已解码**生成**位置，排除 prompt、本来就会计算的行、上一轮必刷行。永久提交的历史块不是本对照的候选。记录块界和绝对行号。Gemma 的 canvas 边界与接受状态单独定义、验证；不照搬 B32。
2. 固定总预算分给上轮刚解码或发生严格编辑的必刷位、MASK 和被加回的前缀位。加回是实际选进模型、重算该行各层并写回 KV；其余前缀沿用可见的驻留 KV。记录硬刷溢出、换走的 MASK 或普通回填、实际各层 Q，不能靠隐藏额外计算制造收益。
3. 原版全算作质量锚点；同预算先做零加回、同席位均匀随机加回、无 logits 的信号加回。随机和信号组使用相同的候选定义、启用条件、席位上限和换出规则；随机用独立、可复现的选位 RNG。零加回把可用席位还给常规窗口。随机是最低限度要做的对照，不预设其表现最差。
4. 两个问题分开判：随机优于零加回，是“花预算刷新一部分前缀”有价值的证据；信号优于同席位随机，才是“识别哪些前缀值得刷新”有价值的证据。原生未来标签只能作诊断上界，不作可部署信号。必要时区分只刷新 KV 与允许写回 token。主表报告固定 30 题逐题质量得失、宏平均 TPF、实际物理 Q 和 token efficiency，而不把命中率当作最终目标。
