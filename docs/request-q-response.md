# 单请求执行器与预算响应实验

[用户原文（逐字归档）](request-q-response-target.original.md) 定义目标，不指定实现。原文件 SHA-256：`a3cb84085550264f15168c9f335fe7dfde400aabab93f306752eda96cdcde280`。以下是本项目的执行与验证决定。

## 先固定执行器

停止把小样本表现最好的前缀刷新、接受规则和开块阈值拼成“最终方法”。把 [Live v1](live-profile-v1.md) 的两套具名配置冻结为**严格预算迁移对照**，不再搜它的参数。它有十档独立固定 90 题结果和有向切换的功能回放，但不满足新定义中的超预算入块；尤其不能把十个总体均值当成十条状态预测。旧版未在所有档位同时超过 IBS / Flow。

新候选只作一个语义改动：**引入后续物理块时支付一次完整 admission，其余步骤沿用冻结的模型配置**。两个模型共用如下生命周期，而非强求两个原生采样器相同：

1. 请求完成 prompt prefill 后接收外层的 rolling `q`，从小档也能开始。LLaDA B32 的五档为 4/8/16/32/64；Gemma B256 为 32/64/128/256/512。切档不重置请求，不预读下一档。
2. 常规去噪先安排此前写入的 token（含 T2T）所欠的 KV 刷新；其余位置由冻结的 MASK 和本物理块内前缀策略选择。跨块按物理块因果掩码，块内双向。只有实际投影的位置有资格参与采样；是否接受由对应模型的已冻结规则决定。
3. 首次引入后续块时，一次投影它全部有效 MASK，满足原生采样条件的位置同轮采样。前块可以同时有实际工作，但同一物理调用只能记一次 F，行按块拆账且不重复。已有未支付写回不能被 admission 覆盖；若先独立还账，其 F 也计入。降档不丢状态，重复访问已建立块不是新的 admission。前块 EOS 使后块投机工作作废时不退账。包括没有提前开后块、在退休时才首次引入后块的路径；已有后块因 encoder epoch 改变而重新建立必须记为 rebuild。
4. 按模型规则处理 EOS、退休、验证及 Gemma encoder。分别报 rolling offer、实际 rolling Q、admission Q、含验证/刷新/重建的全部 decoder F、encoder F、实际读历史 KV 的 decoder Q。初始 prompt prefill 单列。普通轮仍要查超额；仅允许凭真实新块身份、全量物理行与计数放行。候选未经轨迹验证和固定 90 题测试不能替代 v1，更不能把 v1 的成绩贴到它上面。

## 每个决策点预测什么

第一版使用明确反事实：从同一已执行状态 `S`，仅改变**下一次** offer，之后五臂统一回到 LLaDA Q16 / Gemma Q128，直到正常结束或达到相同上限。定义局部标签 `Y(q,S) = (N_final - N_irrevocable_before) / F_from_decision_to_end`。分子扣除分叉前**已不可撤销交付**的非特殊 token，不扣仅临时采纳的 token；分母包含从本次干预起的所有生成 forward。预测 `E[Y(q,S)]`；同一行五个点对应相同 continuation。对照臂也完整执行。另报第一步实际接受/编辑、F、各类 Q、整请求 `N/F` 和质量；不用单步接受数充当 TPF。该估计量回答“一步换档后恢复相同策略”的问题，不表示“从现在一直用该档”，更不等于部署后混合策略的质量。长后缀可能稀释边际差异，应同时看成对差值与不确定性。

同一请求同一题可从不同预算历史进入多个决策点。五个干预必须共享 prompt、实现/权重、随机数状态、实际 token、KV/epoch、未解与写回集合、采样状态和历史，包括已付账单。通过重放/克隆的状态摘要核对，不一致不生成因果标签。模型输入只取决策前可得的特征：两块未解比例、驻留和欠账、是否有后块、前一档、近期接受/编辑与生命周期。摘要、题号只用于身份审计/分组，不能作为预测特征。最终长度、正确答案、未来 EOS 或步数不入模。

## 何时才说切换有收益

- **执行正确：**两模型分别验证小档真实开块、2B、降档后欠账、EOS/作废、重复 admission 与重编码计费；对照固定预算与混合路径。旧严格版和新 admission 版用不同实现 ID，不合并训练或估计。
- **预测有效：**先做相同 continuation 的仅按档均值基线，再由同状态分叉学习与状态有关的五档响应及相邻差；不假设线性、单调或凹。以请求为单位划分训练和评估，所有历史、状态与五个分叉必须同组。每类状态报告独立题数、覆盖率、预测误差、升降档方向与选错档的损失。无支持或质量证据不足时可记录预测，不授权据此切换。训练数据里的正确率不能代替独立质量验证。
- **策略有效：**在相同题单、预算资源约束下做完整请求检验。对照为固定档、等实际 Q 的预登记时间表（含先大后小）及反向顺序。不是仅靠大档用得更多，或通过改变输出长度“变快”。报告逐题宏平均 TPF、`Σ最终有效输出/Σ选中且读历史KV的decoder Q`、答对数、EOS/截断/失败、实际总 Q/F，以及原 30 / 新 60。不得只报成功样本。倾向一种切换规则之前需独立质量门槛；不设定“越大一定越好”。冻结 90 已被多次使用，不称为全新泛化集。
- **Serving 边界：**本阶段产出给定状态的五档收益、升一档的收益、降一档的损失及其支持度。批次 GPU 时间是另一侧输入，`mean_i P_i(q_i|S_i) / T_GPU(q_vector)` 是用户定义的联合目标，不是已经测得的端到端 goodput。当前不实现多请求调度器。

## 可运行的首版预测器

[`request_response.curve`](../bdlm_serving/methods/t2t/request_response.py) 接受当前请求状态，在同模型、同执行器和同 continuation 的五臂样本中估计五个 TPF。先匹配是否有后块以及采样/验证阶段，再按块宽归一化的状态距离为每个训练请求选一个最近状态；五档使用完全相同的邻居。默认距离不超过 0.25、最多 12 个独立请求、少于 4 个就返回 `unsupported`。这些是首版预设，不是从测试集反推的最佳参数。相邻档返回有符号收益和题间成对标准误（不是单请求预测区间）。独立质量门槛默认不给任何档放行；调用方不能拿某一状态的高 TPF 当作质量合格凭证。

在已收齐且通过物理状态核验的紧凑五臂 JSONL 上运行 `python -m tools.request_response_eval <forks.jsonl>`，分别对每个执行器版本和 continuation 做留一题验证，并在**同一批有支持的决策点**比较状态模型和仅按档估计。`total_decisions` 与 `supported_decisions` 同报；没有足够数据时不产生指标。输入字段与边界案例见[测试](../tests/test_request_response.py)。这些单元测试使用构造数据，不是 GPU 结果。

[LLaDA 首批两个同题状态的 GPU 五臂](../experiments/t2t/serving_slots/controls/request-q-response/README.md)已核对真实 KV、RNG 和各阶段账单。另有一项冻结前的选择依据：[Gemma Q128 前缀减配正式 90 题](../experiments/t2t/serving_slots/controls/frontier-dose/formal90-summary.json)。与原 Live 相比 88→86 题、TPF 13.047→12.835、TE 11.97%→11.77%；原 30 是 30→30、新 60 是 58→56。六题的小幅提升未复现，减配不进入冻结候选。

`recommend_adjacent` 是用于比较策略的保守接口，不是调度器：仅在外层可行且另经质量验证的相邻档中，选择预期 TPF 提升超过一份成对标准误的档。没超过、无历史支持或无可比观测时维持原档；原档本身不再可行/合格时返回无建议，交由外层处理。标准误阈值是实验参数，不是质量保证；须与同实际预算的真实混合路径对照后再用于服务。
